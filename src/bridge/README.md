# src/bridge

The edit script that runs inside the game page (`dist/studio-edit.js`).
Publishes `window.studio`, finds an adapter, runs the self-check, turns
pointer/touch input into adapter calls, draws the handles (DOM inside the game
page) and talks to the shell with `studio:*` messages. See CONTRACT.md §1–2.

- `main.ts` — entry: built-in probes + startBridge
- `bridge.ts` — global API, adapter discovery, message routing
- `editor.ts` — edit session: messages → adapter, draw loop, key/step runs
- `early-press.ts` — a tap in the game while the editor is still getting ready: kept, and the editor picks what was under it when it begins (first-click pass, 2026-10-20)
- `input.ts` — gestures (select, Shift/box selection, dragging the picked object, look around, pan, pinch, wheel), the tool strip's chosen tool (a button / M H T S chooses it, then a drag anywhere uses it; Option, right drag, Space or two fingers look around) and the outlines (cached `adapter.silhouette`)
- `handles.ts` — what is drawn on the game: the tool strip (the chosen tool stays pressed), the readout while a drag works, the first-time "how to look around" line, the orange outline and name tag of the selection, the violet marks of the AI's change, stand-ins, the box
- `rise.ts` — camera up / down: the ↑↓ buttons in the game's bottom-right corner (3D adapters with `view.rise`); input.ts does their click / hold / drag and the E / Q keys (with `view.fly`, E / Q fly up / down while held, with W A S D: input.ts's header has the rules)
- `seen.ts` — when a pick from the list moves the edit camera (2026-10-23): "seen" = a fifth of the object on screen (then the camera stays), and a slide to a hidden one never leaves it under 1/6 of the frame (pure maths, `test/seen.test.ts`)
- `snap.ts` — snap to surfaces (3D): the height drag's stop on the surface below (pull 30 px past it to go through), PgDn's stop, several objects (the first to touch), Ctrl / ⌥ to move without snapping; the adapter finds the surfaces (three: `adapters/three/surface.js`)
- `group.ts` — moving, turning and resizing several selected objects together
- `play-ask.ts` — ▶ Play only: ask your AI without stopping the game (` or the corner mark opens a field over the game, full screen too); sends the words with the moment (a screenshot of the game with its HTML UI, the player's camera and what is near through the adapter, the console's errors and last lines) and shows the AI's progress in one line at the top (CONTRACT.md §3.5). Its "fixed" line goes by itself once read (`../shell/line-fade.ts`)
- `play-arrange.ts` — ▶ Play only: the editor's draft placement.json (saved or not) put on the page — moves, draw orders, copies, deletions — only where the page still shows its code's layout, so a game whose loader read the same draft is untouched (a try of the editor, 2026-10-21)
- `play-pause.ts` — ▶ Play only: pause (P, or ❚❚ left of the corner mark) — holds the frames (core time), the clock (`../core/play-clock.ts`), the sound and the key presses, and lets go of exactly that on Resume (2026-10-22, CONTRACT.md §3.5.1)
- `play-chat.ts` — the chat over the paused game: each message a `play` request marked `paused` (the first with the moment, the next with the talk so far), the AI's status notes as replies; P / Escape / Resume go back to the game
- `play-move.ts` — stage 2 of the pause: Move in the paused panel wakes `editor.ts` inside the paused game (the same pick, strip and snap; the player's camera; `paused: true`), with a card in the panel: "Only in this play" → Put in layout (a move as in Edit: Save · N) / Put back; what the game moves itself is "Just for this moment" (2026-10-22, CONTRACT.md §3.5.2)
- `play-switch.ts` — ▶ Play and back to Edit in the same page (fast switch, 2026-10-22, CONTRACT.md §3.5.3; `studio:core/play`): Play keeps the layout, puts the editor's tools away, starts the draft's motions (every `when`, through the game's loader's play hook since studio-no-reload) and lets the game run (frames, clock, sound) with `play-ask.ts` awake; Edit holds the game as a pause does, puts every object back where Play found it and brings the editor back on the same camera. `play-ask.ts` sleeps in the edit page until then (`standby`)
- `play-shot.ts` — the picture for a request made while playing: the canvases and the HTML UI over them painted into one JPEG by a small painter (boxes, borders, text, the game's own images; no library, nothing async); what it leaves out is listed at its head
- `selfcheck.ts` — adapter self-check
- `ui-extras.ts` — UI stages 2–3 (2026-10-22, CONTRACT.md §1.11): the game's screens (`data-studio-screen`) shown one at a time, sample values, an element's text / size / colours and a button's states (the page's `:hover` / `:active` / `:disabled` rules copied onto `[data-studio-state]`), the theme's CSS variables; all put back at the end of editing except the looks and the theme. Made by `editor.ts` for the built-in DOM UI only
- `timeline-path.ts` — the timeline (studio-timeline, 2026-10-22; replaces motion-gui's `motion.ts`): the poses the shell works out for the time line (set through the copy/delete layer, reported to nobody), and the picked object's path in 3D — the curve it follows through its position keys (the loader's own `trackAt`), its shadow at the place's height and a dashed drop from each key so heights read, a dot per key to drag on the ground (Shift: up / down)
