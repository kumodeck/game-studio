# test

Unit tests run with `node --experimental-strip-types --test test/<file>`.
Browser checks run headless.

- `first-run.test.mjs` — the first 5 minutes without a browser: starters read from the agreed shape (`starter.json`), only the game copied (no thumb / README / hand-off notes), never overwriting, the three-crates / pixi-garden fallback, the real CLI's `studio: no-game` (exit 4) / `--starters` / `--starter`, the intro's steps, and the Node check (with a real old Node when one is installed, or `STUDIO_OLD_NODE=<node>`). Fake starters in `first-run/`
- `studio-first5.browser.mjs` — the same in a headless browser: an empty folder → `--starter 3d` → the editor → the intro 1/4 pick → 2/4 drag → 3/4 ask → 4/4 Save → gone (prefs.json `intro: 4`), not back after a reload or a restart; the close button; the phone's "Tap". `--real` (the plugin's own starters or the fallback), `--starters-dir <dir>`, `--shots <dir>`, `--video <file.mp4>` (Chrome screencast → ffmpeg), `--lang ja`
- `studio-e2e.browser.mjs` — the whole studio per example (select, the tool strip, dragging the picked object, undo, the draft written quietly, Save, Assets, a next step from ⌘K)
- `studio-transform.browser.mjs` — resizing several together / each in place (feet on the ground, one undo step) and the 3D turn axes (turn / tip forward / tip sideways around the box middle, R), saved `t` and reopened: three-crates PC and phone, pixi-garden PC. `--shots <dir>`
- `studio-tool-modes.browser.mjs` — the tool strip's tools: a tap on a button chooses it (it stays pressed; the first time, a line on how to look around), then a drag from anywhere (not on the object) does it — height, turn (15° steps), size, move — with a readout next to the strip, one undo step, the view unchanged; Option-drag / right-drag (mouse) and two fingers (touch) look around without touching the object; M / H / T / S in the game frame and in the editor page, Escape drops the tool first; several picked turn together; nothing picked = look around: three-crates PC and phone, pixi-garden PC. `--shots <dir>`, `--only pc|phone`
- `studio-thumbs.browser.mjs` — the list's pictures with hundreds of objects (pixi-garden + a crowd, 283): scrolled through top to end, every row in view gets its picture; one picked far down shows its row, and on a phone the sheet opened with it picked keeps the object above the sheet. PC and phone. `--shots <dir>`
- `rebrand-shots.browser.mjs` — pictures of the six screens of the design (open, one picked, three picked, after the AI added 3, ⌘K, Assets) at PC 1280 and phone 390, dark and light: `--shots <dir> [--theme dark|light|both] [--only pc|phone] [--lang ja|en]`; `three-crates-crowd` / `pixi-garden-crowd` add a crowd in the temporary copy (240 objects from 120 files / 283 from 95) to judge the list, ⌘K and Assets with hundreds of things
- `studio-ai-partner.browser.mjs` — the AI partner editor: game name as title, ask box → `.studio/requests/`, "name it", the AI status line (received / done / "say look" after 20 s), ideas for your AI, 3D focus from the list, no 0 marks in the library; several picked with "Select" (picking several) → one ask about all of them; the Library's "ask my AI to delete" kept as a request; the `studio: unnamed` line. `--lang ja`, `--shots <dir>`, `--no-nudge`
- `web-demo.browser.mjs` — the browser-only web demo (`scripts/build-web-demo.mjs`) served like KUMODeck's test version (`web-demo-host.mjs`): sample list → editor, pick and drag, Save pressed with real input ("saved in this browser"; the same spot pressed again changes nothing), ask (the words stay, "not connected to an AI", no nudge), reopen → still moved, nothing from another origin. three-crates and pixi-garden, PC 1280 and phone 280. `--dir <built folder>`, `--shots <dir>`, `--lang ja|en`, `--plain` (python3 -m http.server instead), `--url <hosted demo>` (the same steps against a hosted copy)
- `web-demo-host.mjs` — the static server the test uses: the test-version bar in every HTML page (and so in the game's frame), a sub path, the host's cache headers / ETags / 304, 308 for a folder without "/", 404 HTML pages, a CSP without https:
- `studio-ai-feel.browser.mjs` — asking the AI (AI feel, 10/16), three-crates PC and phone, with a stand-in agent (`ai-feel/fake-agent.mjs`): pressing the input doesn't open ⌘K (a word that names an action suggests it, a sentence never), nobody watching → said within 2 s with what to do, the agent starts → "has it" → its note with the violet light → no reload while it writes, then the game reloads by itself after "done" behind the old picture (never an empty list or no game), camera and selection kept, only the 3 new crates violet; "Undo AI change" / "Redo" one press each; with the agent watching, "has it" ~0.5 s after Enter. `--shots <dir>`, `--only pc|phone`, `--lang ja`; `--film <out.mp4> [--game lantern-cove] [--phone]` records the whole flow
- `ai-flow.test.ts` — the same rules without a browser: what the AI line says per state, when the game reloads, when typing opens the ⌘K list
- `ai-feel/` — `fake-agent.mjs`, the stand-in agent (`--watch`, received → working → two file writes → done; leaves an `undone` alone)
- `lifecycle.test.mjs` — how a real AI starts and stops the editor: `--detach` returns with `ready <url> pid <n>` and the editor outlives its starter's whole process group (a Codex turn ending), the same line twice reuses the editor / opens the same sample, `--stop` stops this folder's editor and watch by pid and leaves another folder's editor alone, the EPERM line
- `handoff.test.mjs` — request / status shapes (`src/schema/handoff.mjs`) and the 3D focus maths (`src/adapters/three/focus.js`)
- `studio-polish.browser.mjs` — the polish pass: the 3D starter opens on the game camera and the first pick glides to 30°; Turn in one tap; a copy is in the game after ▶ Play; no `path:` / "No name" in the list; a game that throws gets one line with Reload; the phone's ⌘K list puts the view back when it closes (`--only <case>`)
- `studio-speed.browser.mjs` — the speed pass: ⌘K "Back to the opening view" (and ⇧F) goes back to the game camera in 3D and to the opening view in 2D; each list picture is drawn once and the list shows before the pictures; a starter opened on its own shows a copy saved in the editor (its loader is current) (`--only <case>`; with `STUDIO_CHROME` pointing at a GPU browser it also requires the way home to glide)
- `names.test.ts` — the shown names (src/shell/names.ts)
- `studio-fit.browser.mjs` — fitting the editor to one game (`.studio/studio.json`, `tools.js`, `ui/`)
- `studio-layers.browser.mjs` — 2D draw order: buttons, Cmd/Ctrl+[ ], dragging in the list (mouse and finger), undo, "to back" stops in front of the ground (`Item.backdrop`), save (`order` in placement.json), reopen. `--lang ja` for Japanese screenshots
- `studio-edit-ops.browser.mjs` — copy, delete, several at once: real copies (three-crates, pixi-garden, canvas-stars; PC and phone), group turn, undo, save (`added` / `removed`), a small "AI" that writes them into the code, reopen; stand-ins on dom-board. `--lang ja` for Japanese screenshots
